Tutorial 1 · first session

From install to useful work.

You will install Ainz, select a provider, run a real task, approve its tools, and prove the saved session can resume.

01

Install the binary

brew install wess/packages/ainz
ainz --version

Homebrew installs the matching macOS or Linux archive and the ripgrep dependency used by search. Without Homebrew, use the checksum-verifying installer:

curl --proto '=https' --tlsv1.2 -LsSf \
  https://raw.githubusercontent.com/wess/ainz/main/install.sh | sh
02

Open setup

ainz

On a new install, setup opens before chat. Choose a local endpoint, an API-backed provider, or an authenticated coding CLI already on the machine. Ainz reads available models from the provider when it can. Save the selection; /model returns here later.

03

Run one bounded task

ainz ask "inspect this repository and explain how its tests are organized"

ask runs the same engine without the full-screen interface. For an interactive session, run ainz and type the request at the prompt. Start with a concrete read-only task so you can see the transcript, tool calls, and final answer without changing the project.

04

Approve a useful change

Ask Ainz to make a small edit and run its focused test. In the default ask mode, reads proceed while writes, commands, and network calls stop for a decision. Press y once, n to refuse, or a to allow that class of call in the future.

/rules
/permissions ask

/rules shows remembered decisions. Keep ask on until the boundary matches the project.

05

Use the working interface

Type / to search commands and @ to complete a workspace path. Ctrl+O expands tool output, Esc twice brings the last prompt back for editing, and Ctrl+V attaches a clipboard image. Ctrl+L toggles the agent roster.

/goal make the focused test pass
/goal continue

A goal takes repeated turns until it is met or reaches its safety limit. Typing pauses it so you stay in control.

06

Resume what you saved

ainz sessions
ainz resume
ainz sessions export SESSION_ID --out session.md

Close Ainz, run ainz resume, and confirm the transcript returns. Sessions are trees: resuming an earlier node creates another path instead of erasing the original result.
