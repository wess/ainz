Tutorial 4 · sustained operation

Keep long work bounded and recoverable.

Combine goals, session branches, command confinement, specialized children, hooks, and noninteractive control without giving up visible boundaries.

01

Run toward an explicit goal

/goal make the focused test suite pass
/goal continue

A goal continues across turns until the model marks it complete, it reaches 25 turns, or you type. Use the plan and transcript as checkpoints; a goal is persistence, not permission to widen the task.

02

Recover instead of restarting

ainz sessions --search "sandbox failure"
ainz resume SESSION_ID
ainz resume SESSION_ID --at NODE_ID "try the smaller fix"

Every completed turn is saved. Resume the active path after interruption, or branch from an earlier node to try another approach while preserving the original work.

03

Confine commands

AINZ_SANDBOX=workspace ainz
AINZ_SANDBOX=strict ainz
ainz doctor

workspace keeps command writes inside the workspace and temporary directories. strict also cuts network access. Reads are not confined, and builds that need caches outside the workspace may fail. If Ainz cannot provide the requested boundary, it refuses the command instead of silently running it unconfined.

04

Delegate to a named agent

Create .ainz/agents/reviewer.md:

---
name: reviewer
description: Review changes without modifying the workspace
tools: read, list, search
disallowedTools: shell
permissionMode: read-only
maxTurns: 8
---
Review the implementation and tests. Report concrete bugs with file references.

Run ainz agents to confirm discovery. A child cannot widen its parent's permissions or turn limit, and keeps its own switchable buffer and saved session.

05

Put policy before execution

-- init.lua
ainz.on("pre_tool", function(call)
  if call.name == "shell" and call.subject:find("git push", 1, true) then
    return false, "pushing is reserved for the operator"
  end
end)

A Lua pre_tool handler runs in every permission mode and for subagents. For repository-owned checks, a process hook can receive the same event as JSON and block by exiting non-zero.

06

Use a persistent control surface

ainz ask --json "summarize this workspace"
ainz rpc --permissions auto

JSON event mode fits one-shot automation. RPC keeps one initialized session and tool catalog alive while a host sends prompt, steer, cancel, state, and save requests. Neither surface opens an approval prompt, so grant auto only when the host is meant to mutate the workspace, or cover narrower calls with standing rules.

07

Connect memory and improvement carefully

ainz synapse connect --mesh
/improve on
/improve

Synapse can share durable memory, guidance, skills, and the agent roster across tools. Automatic improvement is opt-in: it proposes a harness change from saved runs, checks source and behavior in an isolated worktree, then waits for review before installation. Treat a proposal as code review, not as an update notification.
