Tutorial 3 · extension package

Give the model one new tool.

Build a Lua plugin that reads a project file, returns structured output, and asks for no more authority than it uses.

01

Create the bundle

mkdir -p .ainz/plugins/projectinfo/lua
touch .ainz/plugins/projectinfo/plugin.toml
touch .ainz/plugins/projectinfo/main.lua

A project plugin travels with the checkout. A user plugin goes in the Ainz config directory's plugins/ folder instead.

02

Declare the boundary

capabilities = ["workspace_read"]

[plugin]
name = "projectinfo"
version = "0.1.0"

[runtime]
kind = "lua"
path = "main.lua"
timeout_ms = 30000
memory_bytes = 67108864
fuel = 10000000

[[tools]]
name = "summary"
description = "Read a project file and return a short structural summary"
capabilities = ["workspace_read"]
parameters = { type = "object", properties = { path = { type = "string" } }, required = ["path"] }

The exposed tool is named projectinfo_summary. Every tool declares a subset of the bundle's capabilities, so a read-only tool cannot borrow write or process authority.

03

Implement the tool

local function lines(text)
  local count = 0
  for _ in text:gmatch("[^\n]+") do count = count + 1 end
  return count
end

return {
  summary = function(args)
    local text = ainz.read(args.path)
    return { path = args.path, bytes = #text, lines = lines(text) }
  end,
}

The function receives validated arguments as a Lua table. Return a string for plain output or a table for JSON. Use error("message") for a failure the model can act on.

04

Inspect and approve it

ainz plugins list
ainz plugins approve projectinfo

Approval prints the runtime, directory, and capabilities being trusted. It pins the manifest and every file in the bundle. Start Ainz and ask it to use projectinfo_summary on Cargo.toml.

05

Split reusable code into a module

-- lua/text.lua
local M = {}
function M.lines(value)
  local count = 0
  for _ in value:gmatch("[^\n]+") do count = count + 1 end
  return count
end
return M

-- main.lua
local text = require("text")

require resolves only inside the approved bundle. There is no ambient module path or native module loading.

06

Reapprove changes deliberately

Edit either Lua file and run Ainz again. The plugin returns to pending because its content no longer matches the approved digest.

ainz plugins approve projectinfo
ainz plugins revoke projectinfo

This is the development loop: change, inspect, approve, exercise. Do not use --yeet as the normal plugin workflow; it deliberately bypasses every plugin approval for that run.

07

Choose another runtime when needed

Lua plugins are the shortest path for bounded tools. A WebAssembly component is useful when host authority must stay capability-scoped across a compiled boundary. A process plugin fits an existing trusted executable, but it runs with the user's environment and cannot be sandboxed by its manifest. Portable Agent Plugin packages can bundle skills and MCP servers for compatible clients.

The extension reference links to the complete manifests, host functions, wire protocol, and trust model.
