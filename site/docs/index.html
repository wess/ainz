Install

Homebrew

brew install wess/packages/agentx

Verified installer

curl --proto '=https' --tlsv1.2 -LsSf \
  https://raw.githubusercontent.com/wess/agentx/main/install.sh | sh

Cargo

cargo install --git https://github.com/wess/agentx --tag v0.1.2 --locked

Release archives are available for Intel and Apple Silicon macOS, and x86_64 and arm64 Linux.

Providers and models

Run agentx without a configured model to enter setup, or use /config later. The same operations are scriptable:

agentx providers list
agentx providers add ollama --preset ollama
agentx models list ollama --refresh
agentx providers use ollama qwen3:8b

HTTP providers use AgentX's tool loop. Codex and Claude Code presets launch their installed, authenticated CLIs headlessly and return their final response as an AgentX turn. Permission mode is carried into those runs.

Use agentx doctor to print the active provider, model, configuration and session paths, and plugin approval counts.

Configuration

Configuration is stored in the platform user config directory. Environment variables and flags override it.

endpoint = "http://127.0.0.1:11434/v1"
model = "qwen3:8b"
api_key_env = "AGENTX_API_KEY"
permissions = "ask"
context_tokens = 128000
compact_at_tokens = 96000
preserve_messages = 8

Named providers live under [providers.NAME] with provider selecting the active one, and the [ui] table remembers the roster and header choices; the CLI and the TUI manage all three. Environment variables are AGENTX_MODEL, AGENTX_ENDPOINT, AGENTX_PROVIDER, AGENTX_API_KEY, AGENTX_CONFIG, and AGENTX_MCP_PROFILE. Use a provider's api_key_env field to keep the secret itself outside configuration files.

Extensions

MCP

agentx mcp add NAME --required -- COMMAND ARG…
agentx mcp

Stdio servers are registered from the CLI; Streamable HTTP servers are added to the profile file in the user config directory. Tool schemas stay out of model context until searched and selected.

Skills and commands

AgentX reads the layouts other harnesses already use, so an existing project needs no import step. AGENTS.md and CLAUDE.md are both read at every level from the filesystem root down to the workspace, nearest last. Skills are discovered from .claude/skills/, .agents/skills/, skills/ and .agentx/skills/ beside the workspace, plus ~/.claude/skills/ and the config directory; their names and descriptions occupy the prompt and one skill tool loads the text on demand, including any scripts or reference files bundled beside it. Prompt templates come from .claude/commands/ and .agentx/prompts/, namespace by subdirectory as /api:audit, and expand $ARGUMENTS and $1 as well as {{args}} and {{1}}.

Plugins

AgentX discovers native manifests and portable Agent Plugins 1.0 packages from user and workspace plugin roots. Discovery never executes a plugin; approve its content hash first:

agentx plugins list
agentx plugins approve NAME
agentx plugins revoke NAME

See the repository guides for plugin manifests, custom headers (paint one in the masthead studio), MCP, and custom providers.

Synapse

agentx mcp add synapse --required -- /path/to/synapse mcp

Synapse can also pass --mcp-config FILE when it launches AgentX. Harness integration goes through JSON-RPC mode.

Security model

Permission modes are ask, auto, and read_only. JSON mode never opens an approval prompt, so noninteractive mutation requires explicit --permissions auto. Component plugins receive bounded resources and capability-checked imports. Process plugins are native programs and cannot be sandboxed by a manifest; treat them as trusted code. Plugin approval is pinned to the manifest, the plugin directory, and the runtime artifact, which is rechecked when it runs, so a change returns the plugin to pending.

Report vulnerabilities privately through the repository's security advisory form.
